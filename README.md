# 絶叫！タワービルダー

振り子のように揺れるクレーンから階を落とし、3階層の連鎖崩壊が起きるまで高さを競うゲームです。TypeScript、Vite、Matter.js、Canvas 2Dで実装しています。

## 起動

GitHubで受け取った場合は、[単体HTML](downloads/tower-builder.html) をダウンロードすると、インストールなしで遊べます。[配布用ZIP](downloads/tower-builder.zip) にもソースと公開用ビルドが入っています。

Node.js 20.19以降の20系、または22.12以降を用意します。

```sh
npm install
npm run dev
```

端末に表示されたURLをPCブラウザで開きます。配布版の `tower-builder.html` は、ファイルをブラウザで直接開いてオフラインで遊べます。ファイルURLでベストスコアを保存できるかはブラウザの設定に依存します。開発サーバーまたは公開URLでは、同じブラウザとオリジンで記録を引き継ぎます。

## 操作

| 操作 | 内容 |
| --- | --- |
| Space、現場をクリック、または「ブロックを投下」 | ワイヤーを切って落とす |
| 「もう一度プレイ」 | ゲームオーバーから新しい建設を始める |
| 「サウンド」 | ミュートの切り替え |
| 「設定」 | 音量とデバッグ用の物理設定 |

黄色の照準は、現在の揺れと水平速度から求めた着地位置の目安です。飛行中の他のブロックや、傾いた足場との衝突で軌道は変わります。小型階などを見送る場合は、照準が足場から大きく外れるタイミングで投下します。場外投棄にスコア減点や回数制限はありません。

「次のブロック」には、現在吊られているブロックか、補充中であれば次に吊られるブロックが表示されます。補充時間の720 msが過ぎれば、前の階がまだ揺れていても投下できます。

## ブロックとスコア

| 形状 | 寸法 | 特徴 |
| --- | --- | --- |
| 標準階 | 80 × 40 | 4枚の窓。幅が広く着地範囲を確保しやすい |
| 縦長階 | 40 × 80 | 3段の窓。高さを稼げるが、傾きやすい |
| 小型階 | 40 × 40 | 2枚の窓。上に積む階の接地範囲が狭い |

形状と物理特性は独立に抽選されます。標準は黄、重量は赤茶で底部に斜線、低摩擦は青緑で底部に横線があります。序盤は標準の形状・特性が出やすく、最高到達高度が高くなるにつれて振り子の振れ幅と速さが増します。

基礎の上面から、建物に組み込まれた階の頂点のうち最も高い点までが現在の高さです。物理座標10単位をゲーム内の1 mとして、小数第1位まで表示します。未着地・未組み込みの階と場外に落ちた階は集計対象外です。短い接触の途切れでは高さ表示を最大90 ms維持します。最高到達高度は建物が低くなっても保持され、ベストスコアは `localStorage` に保存されます。

## 連鎖崩壊の判定

物理演算は60 Hzの固定時間ステップです。基礎だけが固定され、投下済みのブロックはすべて動き続けます。回転した階や横倒しになった階も、基礎から支持されれば上に積み増せます。

1. Matter.jsの有効な衝突ペアから、垂直成分のある下支えを抽出します。基礎から接触をたどって到達できるブロックを支持中とします。
2. 支持されている状態で速度と角速度が十分低い時間が210 ms続くと、既存の建物に組み込まれます。
3. 組み込まれたブロックが支持を失い、安定した支持に戻らないまま230 ms以上が経過し、重心が直前の安定位置から28単位以上落ちたら崩落とします。一瞬の接触切れや小さな振動は猶予時間で吸収されます。組み込まれたブロックが場外に出た場合も崩落として数えます。
4. 最後に別の階が崩落した時刻から1,250 ms以内の崩落を同じ連鎖にまとめます。同じブロックIDは連鎖内で一度だけ数えます。低い位置で安定して組み込まれ直したブロックは、別の連鎖の対象になることがあります。
5. 連鎖が3階層に達すると投下を終了します。物理演算と画面描画は続行し、カメラは少し待って崩壊後の高さへ移動します。1〜2階層の崩落後も建設を続けられます。

一度も組み込まれなかったブロックは、建物に接触しても崩落数に加えません。そのブロックとの衝突で既存の階が支持を失った場合は、通常のルールで判定します。

## 調整

「設定」で「デバッグ・物理調整」を開きます。パネルを開いている間はゲームを一時停止します。

- 重力は設定を閉じた直後の物理ステップに反映されます。
- 密度、摩擦、反発は新しく投下するブロックに適用されます。
- 振り子の長さ、振幅、周期は現在の吊り荷に反映されます。
- 形状と特性の抽選は重みの比率で行います。すでに決まった吊り荷を投下すると、変更後の重みで次の荷が抽選されます。形状または特性の重みをすべて0にすると、その分類は標準になります。
- 組み込み時間、崩壊の落下距離と猶予、連鎖の間隔を変更できます。境界線、重心、速度ベクトル、支持と組み込みの状態も重ねて表示できます。
- 初期値と出現率は `src/config.ts` にあります。画面での調整は同じタブのリスタートに引き継がれ、ページの再読み込みで初期値に戻ります。

## 音声とライセンス

- `src/assets/` のMP3は本作向けに作成したオリジナルのフォルマント合成音です。投下時は短い3種類から選び、連鎖崩壊時には長い悲鳴を再生します。外部の録音素材は使っていません。同梱の音声ファイルは商用利用と改変が可能なCC0 1.0として提供します。 [CC0 1.0](https://creativecommons.org/publicdomain/zero/1.0/)
- `scripts/generate_audio.py` で合成内容を変更できます。再生成にはPython 3とFFmpegが必要です。ファイルを差し替えるときは `src/audio.ts` の読み込み先を更新します。プレイやビルドには再生成は不要です。
- Matter.jsのMITライセンス全文は `public/third-party-notices.txt` に記載し、ビルドおよび単体HTMLにも同梱しています。 [Matter.js](https://github.com/liabru/matter-js)

## 検証と静的公開

```sh
npm test
npm run build
npm run preview
```

テストは、8階の連続投下とカメラ追従、横倒しの縦長階への積み増し、小型階の端での転倒、非接触の投棄、1〜3階層の物理崩壊、連鎖時間の境界と重複排除を確認します。ビルド済みJavaScriptのDOMテストでは、Spaceとクリック、リザルト、リスタート、音量設定、スコア保存を再現します。

GitHub Pagesは `main` へのプッシュ時に、GitHub Actionsで `npm ci` と `npm run build` を実行し、`dist/` を公開します。公開パスは `/towerbuilder/` です。ローカルでは、`npm run dev` はルートURLで、`npm run preview` は `/towerbuilder/` で開きます。 [GitHub Pages](https://ttkojiro0526-source.github.io/towerbuilder/)

別のリポジトリで同じデプロイを使う場合は、リポジトリの Settings → Pages → Build and deployment で Source を GitHub Actions に設定し、`vite.config.ts` の公開パスをリポジトリ名に合わせます。

`npm run build:play` は同じビルドから、コード・CSS・音声を埋め込んだ `tower-builder.html` を生成します。
